## 用户的核心诉求

在 Omarchy 顶栏看到当前播放歌曲的**逐行同步高亮歌词**（Spotify 是主要音源）。

## 决策记录（为什么是重写而不是继续修）

1. **等不起**：issue 开了多日，作者在活跃开发别的功能但没回应渲染问题。
2. **偏好**：用户强烈偏好 Rust（原插件 Python 后端被视为负面资产）。用户的其它本地工具（alt-tab-global）已经是 Rust。
3. **重写收益**：后端换 Rust 顺带消灭动态类型 bug（原插件的已知 bug 之一就是字符串/布尔混淆）。
4. **重写成本可控**：协议很简单（MPRIS → LRCLIB → 顶栏 QML），原插件的 manifest 证明 Quickshell 插件只需要两个 QML 入口 + 一个 manifest，后端进程可以用任意语言。

## 与原插件的关系

对标功能，不 fork 代码（语言不同没法直接 fork）。manifest 结构与 Omarchy 插件规范保持兼容，id 计划用 `local.lyrics-rs` 或类似（见 docs/04）。
