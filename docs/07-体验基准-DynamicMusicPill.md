# 07 — 体验金标准：Dynamic Music Pill（GNOME 时代基准）

## 用户在 Ubuntu/GNOME 时代用的是什么

**Dynamic Music Pill**（https://github.com/Andbal23/dynamic-music-pill ，★394，GNOME Shell 扩展，JavaScript）。

用户原话定位：「全网 GNOME 最好用的歌词拓展」「歌词直接长在顶栏里面，和时钟、图标同一行混排」。

这是本项目的**体验金标准**：重写版的验收不只是"能显示歌词"，而是要达到这个扩展的使用手感。

## 它的交互设计（拆解成重写需求）

| 交互 | 细节 | 对本项目的要求 |
|------|------|----------------|
| 药丸驻留顶栏 | 胶囊形媒体控件嵌在 panel 里，带波形可视化动画 | 紧凑态小部件要精致，不是粗糙的一行文字 |
| 点击封面展开歌词 | 点击药丸上的专辑封面 → 展开歌词视图 | BarWidget 点击交互：默认展开歌词面板（原插件 crmne.lyrics 也是点击展开，方向一致） |
| 可滚动歌词视图 | 歌词在可自由滚动的部件里显示，播放中上下滚动 | LyricsView 滚动跟随 + 允许用户手动滚动浏览（手动滚动后要有"回到当前行"机制） |
| 当前行强调 | 当前行**粗体白色**突出显示 | 当前行样式醒目（本项目可用主题强调色+粗体） |
| 点击某行跳播 | 点击歌词行 → 播放器 seek 到该行 | 需要 MPRIS SetPosition 支持；不支持时隐藏该能力 |
| 封面集成 | 封面是药丸的一部分 | artUrl 加载封面缩略图（注意 docs/02 提到的下载安全上限） |

**注意**：用户没提也未必需要的功能——波形可视化动画是它的招牌，但在 Quickshell 顶栏实现成本高，v1 明确不做（见 docs/04 范围红线），用户若点名要再加。

## 演进史上的另一个相关方案（防混淆）

之前会话曾把 **waylyrics**（https://github.com/waylyrics/waylyrics ，★274，**Rust** + GTK4）列为 Wayland 顶置歌词的候选基准，还编译过（产物已清理）。两者区别要分清：

| | Dynamic Music Pill | waylyrics |
|---|---|---|
| 形态 | GNOME Shell 扩展，长在顶栏里 | 独立悬浮窗（胶囊歌词条，可吸附屏幕顶部） |
| 技术栈 | JavaScript（GJS） | Rust（GTK4/libadwaita） |
| 与本项目的距离 | **交互金标准**（抄体验） | 技术近亲（Rust + MPRIS + LRCLIB，可抄实现思路/词源逻辑） |

## 对设计方案的三处修订（已在 docs/04 落实）

1. 展开触发：点击封面/部件展开歌词面板（而非仅 hover 或按钮）。
2. LyricsView 必须支持"手动滚动浏览 + 自动回中"双模式。
3. 点击行 seek 列为标准交互（MPRIS SetPosition 可用时）。

## 备选路线备案（如果重写失败）

如果 Quickshell 插件路线反复受阻（参考 docs/05 风险节），**waylyrics 是一条已验证可用的退路**：它本来就是 Wayland 原生的桌面歌词，Rust 写的、活跃维护（2026-10 还有提交），pacman 里有包（`waylyrics`）。缺点是悬浮窗形态而非顶栏内嵌——但可以把它设为置顶 + 吸附屏幕顶部，视觉上接近用户习惯。**此备案须先问用户再走**。
