## 插件机制（Omarchy 4 / Quattro）

- 插件目录：`~/.config/omarchy/plugins/<id>/`，每个插件一个文件夹。
- 已装插件参考（活例子）：`~/.config/omarchy/plugins/rosakodu.dock/`（第三方 service+bar-widget 插件，结构完整，**做新插件前先读它的源码**）。
- manifest 规范：`manifest.json`，`schemaVersion: 1`，关键字段见 docs/02。
- CLI：`omarchy plugin add <git-url> --enable` / `remove` / `enable` / `disable` / `list` / `validate <folder>`（开发时用 `validate` 校验 manifest）。
- 设置存储：manifest `barWidget.schema` 里声明的键（如 `hideWhenIdle`）会被持久化到用户设置层；**存储层类型不可靠**（docs/03 的 bug 根源），读取时必须自己兜底。

## 重要：本机 `omarchy.media` 处于 disabled 状态

`omarchy plugin list` 显示 Omarchy 自带的 `omarchy.media`（first-party `service,bar-widget`）当前 **disabled**。原 issue 描述"service appears unloaded"——**歌词插件依赖媒体状态源，这可能是相关因素之一**。开发/验收前先确认：要么启用 `omarchy.media`，要么确认我们的插件直接连 MPRIS 不经过它。

## 媒体源

- 用户用 **Spotify** 听歌（网页版/客户端，MPRIS 接口名 `spotify` 或 `org.mpris.MediaPlayer2.spotify`）。
- 验收方式：用户在 Spotify 放一首有歌词的歌，看顶栏是否逐行高亮。**不要拿假数据当验收**。

## 调试方法

- Quickshell 日志：插件报错会进 quickshell 日志。系统里验证 quickshell 状态：`pgrep -af quickshell`。
- 原插件曾"无报错但 service 未加载"——调试时不要只看错误日志，要用 `omarchy plugin list` 确认加载状态 + 主动打日志。
- IPC 调试参考：本机现成例子 `~/.local/src/alt-tab-global/`（Rust + Hyprland unix socket + serde_json，编译产物在 `~/.local/bin/`），它的进程间通信写法可以直接抄。
- Hyprland 查询：`hyprctl` 命令可用（如 `hyprctl activewindow`）。

## 注意：本机有本地补丁，别误伤

- `~/.config/omarchy/plugins/rosakodu.dock/scripts/dock-minimize.py` 有手写补丁（`reveal_user_drawer()`，备份 `.bak-drawer`）——**不要动它，不要覆盖插件目录**。
- Omarchy 更新走 pacman + Snapper 快照，系统级改动会进快照，但 `~/.config` 下的东西不在快照保护内，改前备份。
