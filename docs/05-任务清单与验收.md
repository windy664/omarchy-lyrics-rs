# 05 — 任务清单与验收标准

按顺序执行。**每个阶段的验收都过了才能进下一阶段**，验收标准写死，不许自行放宽。

## 阶段 0：验证线索（预计 30 分钟，可能直接改变后续计划）

| # | 任务 | 验收 |
|---|------|------|
| 0.1 | 按 docs/03 顺序验证三个假设（hideWhenIdle / omarchy.media / Spotify MPRIS） | docs/03 的"验证结果登记"表填完，含日期。**若 hideWhenIdle 假设成立且原插件当场复活，停下来向用户汇报**——用户可能改主意直接用原插件，重写项目是否继续由用户拍板 |

## 阶段 1：Rust 后端骨架（lyricsd）

| # | 任务 | 验收 |
|---|------|------|
| 1.1 | `backend/` Cargo 项目：zbus 连 MPRIS，监听当前 track | 终端跑 `lyricsd`，Spotify 切歌时 stdout 打出 `{"ev":"track",...}` 行，字段齐全 |
| 1.2 | LRCLIB 客户端：`/api/get` 精确 → `/api/search` 兜底 → 都失败发 `{"ev":"status"}` | Spotify 放任意一首知名中文/英文歌，stdout 出 `{"ev":"lines","synced":[...]}`；断网时出 `status` 事件而不是 panic |
| 1.3 | 播放进度 → 当前行计算 | Spotify 播放中，stdout 的 `{"ev":"position"}` 里能算出当前应高亮的行号；暂停时 playing=false |
| 1.4 | 日志落盘 `~/.local/state/omarchy-lyrics-rs/` | 三类关键节点（MPRIS 连接、LRCLIB 请求、错误）都有日志行；`cargo build --release` 无 warning |

## 阶段 2：QML 插件壳

| # | 任务 | 验收 |
|---|------|------|
| 2.1 | `plugin/` 目录：manifest.json + Service.qml + BarWidget.qml + LyricsView.qml | `omarchy plugin validate plugin/` 通过 |
| 2.2 | 安装：`omarchy plugin add <本仓库本地路径或推远的 git> --enable`（安装方式先问用户偏好） | `omarchy plugin list` 出现且 enabled |
| 2.3 | IPC 联调：Service.qml 拉起 lyricsd、解析行式 JSON、后端崩溃自动重启 | `killall lyricsd` 后 30 秒内插件状态恢复；`journalctl`/状态文件里有重启记录 |

## 阶段 3：真机验收（用户参与）

| # | 任务 | 验收 |
|---|------|------|
| 3.1 | **主验收**：用户在 Spotify 放歌 | 顶栏出现小部件，逐行同步高亮，换歌自动跟上，暂停/恢复不闪烁 |
| 3.2 | 降级路径：断网放歌 / 放一首 LRCLIB 没有的歌 | 显示兜底文案，部件不消失，不报错刷屏 |
| 3.3 | 主题验收：手动触发昼夜切换（`omarchy theme set ...`） | 歌词颜色跟随主题，无硬编码颜色残留 |
| 3.4 | hideWhenIdle 验收：暂停播放 | 无播放时部件隐藏（或按设置显示占位），与设置语义一致 |
| 3.5 | 展开面板：点击小部件 | 歌词全文展开，当前行居中，宽度/高度受设置控制 |
